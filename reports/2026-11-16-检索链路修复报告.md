# 检索链路修复报告

- 项目：decompose-agent
- 日期：2026-11-16
- 修改范围：主图检索链路、结构化计划校验、域注册、主链测试、项目文档
- 结论：修复完成，自动化测试 104 项全部通过

## 1. 修改结论

本次修改解决了三个会直接影响项目可信度的问题：

1. 检索工具不再收到裸自然语言字符串，而是收到经过校验的 `arguments` 对象。
2. analytics 域改为显式、可重复执行的注册流程。
3. 测试不再误 patch 旧 ReAct 节点，主图端到端路径已纳入测试。

修复后，用户问题会先被转换为类似下面的结构化计划：

```json
{
  "steps": [
    {
      "question": "查询 prod_a 在 2025-06 的退款数据",
      "tool": "search_refunds",
      "arguments": {
        "product_id": "prod_a",
        "month": "2025-06"
      }
    }
  ]
}
```

`retrieve` 节点只执行计划中的工具，并将 `arguments` 传给工具，不再把完整子问题文本错误绑定到 `product_id`。

## 2. 修复前的问题

### 2.1 自然语言被当成工具参数

原实现位于 `graph.py` 的 `_retrieve`：

```python
raw = await tool.ainvoke(sub_q)
```

这会把“查询三个产品线的退款数据”整段字符串传给 `search_refunds`。工具没有报错，但会把该字符串当成筛选值，最终返回“未找到匹配的退款数据”。

这个问题具有欺骗性：

- HTTP 请求成功。
- LangGraph 链路成功。
- 最终仍然能生成一份报告。
- 但报告中的业务数据实际上不完整或为空。

### 2.2 域注册依赖 import 副作用

原实现中，analytics 域在自己的模块 import 时注册一次。注册表被清空或模块已被缓存后，再次调用 `register_enabled_domains()` 不会重新注册，导致图拿到空工具集。

修复方式是提供显式 `analytics.register()`，并在 `register_enabled_domains()` 中调用。

### 2.3 测试覆盖了旧架构

部分集成测试 patch 的是：

```text
agent_starter.nodes.agent.build_llm
agent_starter.nodes.classify.build_llm
```

当前主图实际使用：

```text
agent_starter.graph.build_llm
```

因此测试没有替换拆解和综合节点使用的 LLM，最终发起真实网络请求。修复后统一通过 `llm_factory` 注入测试用模型。

## 4. 新执行流程

```text
START
  ├─ classify
  └─ recall
          ↓
      decompose
  生成 question + tool + arguments
          ↓
planning.py
  校验 JSON、工具名、参数、步骤数和重复项
          ↓
      retrieve
  asyncio.gather 并行执行各计划步骤
          ↓
     synthesize
  综合结果、参数、状态和偏好
          ↓
        write
          ↓
         END
```

### 失败语义

- 模型输出坏 JSON：使用全量读工具兜底。
- 模型输出未知工具：删除该步骤。
- 参数不符合工具 schema：删除该步骤。
- 所有步骤都无效：使用全量读工具兜底。
- 单个工具运行时异常：该步骤标记为 `status=error`，其他步骤继续。
- 没有工具或没有步骤：空结果继续到综合节点。

## 5. 验证结果

执行环境使用假 LLM 和本地模拟数据，不依赖真实模型网络：

```text
104 passed in 1.25s
```

重点验证场景：

1. 合法计划保留 `prod_a` 和 `2025-06` 参数。
2. 检索结果包含 2025-06 的真实模拟数据，而不是“未找到”。
3. 非 JSON 输出触发四个读工具兜底。
4. 一个工具异常时，另一个工具仍成功。
5. 完整 LangGraph 路径能产出 `AIMessage`。
6. FastAPI 的同步、SSE、会话接口全部通过。
7. 昵称偏好在下一轮综合 Prompt 中出现。

本次没有调用真实 DeepSeek 或 OpenAI 接口，因此真实模型格式遵循率和最终报告质量仍需配置密钥后人工验收。

## 6. 兼容性

- `build_graph(checkpointer=None)` 原调用方式继续可用。
- 新增的 `llm_factory` 是关键字参数，仅用于依赖注入和测试。
- `AgentState` 未增加必填字段。
- 工具仍为 LangChain `@tool`，业务域注册方式保持原结构。
- 旧 ReAct 代码仍保留，但不属于当前主图。

## 7. 剩余风险

1. 计划质量仍依赖模型能否正确生成工具名和参数。
2. 兜底计划执行全量查询，可能产生较宽泛结果。
3. 模拟数据的三条产品线时间范围不同。
4. PostgreSQL/pgvector 路径未做真实集成测试。
5. 尚无真实模型质量评估集、并发基准和长期运行测试。
6. 当前 `classify` 结果尚未用于限制可选工具集合。
